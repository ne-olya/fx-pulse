## 1. Цель ночи

Сквозной работающий конвейер:

```
загрузка данных → проверка качества → индикаторы → signals_as_of(T) → бэктест walk-forward → метрики
```

Лучше узкий, но замкнутый и воспроизводимый путь, чем широкий и недоделанный. Один ряд и малая сетка параметров — достаточно. Ширину добавим завтра.

**Готово, когда выполнены все пять условий:**

1. `make setup && make data && make backtest` отрабатывает с нуля на чистой машине.
2. Тест на заглядывание вперёд проходит (раздел 5).
3. Есть `artifacts/signals.csv` — таблица сигналов в схеме из раздела 4.3.
4. Есть `artifacts/metrics.csv` — матрица «индикатор × ряд × горизонт × метрики».
5. Есть `docs/data-quality.md` — отчёт по чек-листу раздела 3.2.

## 2. Чего НЕ делать

Список жёсткий. Нарушение любого пункта обесценивает результат целиком.

* **Никакого заглядывания вперёд.** Сигнал на дату `T` считается только по данным, доступным на `T`. Это дисквалифицирующее условие кейса.
* **Никаких генеративных моделей внутри сигнального контура.** Только классический ML и статистика. Сигнал обязан быть объяснимым.
* **Не подбирать пороги «на глаз» по итоговой метрике.** Сетка регистрируется до прогона (раздел 6).
* **Не строить сообщения о будущем.** Прототип не пишет тексты; если понадобится заглушка — только факт о прошлом или настоящем.
* **Никаких персональных и внутренних банковских данных.** Только открытые воспроизводимые источники.
* **Не коммитить содержимое `data/`** — оно в `.gitignore`. В репозиторий идут загрузчики, не выгрузки.
* **Не изобретать метрики.** Определения зафиксированы в разделе 7, менять их нельзя без согласования.

### 4.1. Панель

Ключевое требование: у каждого наблюдения две даты — **когда значение стало известно** и **на какую дату оно действует**. Всё остальное строится на этом различии.

```python
def load_panel(series: str) -> pd.DataFrame:
    """
    Колонки:
      known_at    — момент, когда значение стало публично известно (МСК)
      value_date  — дата, на которую значение действует
      series_id   — 'CBR:TJS', 'MOEX:CNYRUB_TOM', 'NB:KZ', ...
      price       — рублей за единицу иностранной валюты
      is_carried  — значение перенесено с предыдущего дня
      meta        — объём, число сделок и прочее, если есть
    """
```

**Ориентация цены зафиксирована и менять её нельзя:** `price` = рублей за единицу иностранной валюты. **Меньше = лучше для клиента** (дешевле купить валюту получателя).

Для ряда ЦБ: курс на дату действия `T+1` публикуется в течение дня `T`, поэтому `known_at ≈ T 15:30 МСК`, `value_date = T+1`.

### 4.2. Индикаторы

Единая сигнатура: на вход — панель, урезанная до `as_of`, на выход — булев признак срабатывания и сила.

```python
@indicator("level_percentile")
def level_percentile(panel: pd.DataFrame, window: int, pct: float) -> IndicatorOut:
    """Курс в нижних pct процентилях за window наблюдений."""
```

Реализовать из ТЗ п. 2:

| Индикатор | Параметры сетки |
|---|---|
| `level_percentile` — уровень | `window` = 30/60/90/180/252, `pct` = 5/10/20 |
| `momentum_streak` — N дней подряд вниз | `n` = 2/3/4/5 |
| `filter_rule` — движение более x % | `x` = 0.5/1/2/3 |
| `reversal_from_low` — отскок от минимума | `lookback` = 20/60/90, `bounce` = 0.5/1.0/1.5 (в дневных σ) |
| `volatility_regime` — режим по реализованной волатильности | `window` = 20, терцили |
| `seasonality` — календарный профиль | месяц, день месяца, праздники стран-получателей |

**Пороги и барьеры задавать в долях дневной σ ряда, а не в абсолютных базисных пунктах.** Иначе параметры не переносятся между рядами, а перенос — прямое требование кейса.

### 4.3. Сигналы

```python
def signals_as_of(T: datetime, config: Config) -> pd.DataFrame:
    """
    Сигналы ровно в том виде, в каком они выглядели бы на дату T.
    Использует ТОЛЬКО наблюдения с known_at <= T.

    Колонки:
      date         дата среза
      corridor     RUB->TJS | RUB->UZS | RUB->KGS | RUB->AMD | RUB->KZT

      scenario     T1..T5 по портфелю типов сообщений (plan.md, 3.2)
    """
```

Это **центральная функция всего решения**. Писать её первой, до индикаторов и бэктеста. Бэктест — цикл по датам с вызовом этой функции, а не отдельная реализация той же логики.

## 5. Тест на заглядывание вперёд

Дисквалифицирующее условие кейса, поэтому тест обязателен и должен быть в CI-подобном виде (`make test`).

**Формулировка теста:** для случайной выборки из ≥ 50 дат `T`

```
signals_as_of(T, полный_датасет) == signals_as_of(T, датасет_урезанный_по_T)
```

Результаты должны совпадать **побитово**. Если совпадения нет — где-то течёт будущее.

Дополнительно:

* Загрузка панели с параметром `as_of` физически отбрасывает строки с `known_at > as_of` — на уровне загрузчика, а не фильтром в конце.
* Разметка целевой переменной живёт отдельно от признаков и никогда не попадает в фичи.
* Любая нормализация (σ, перцентили, скейлеры) считается только по прошлому окну — глобальные `fit` на всей истории запрещены.

## 6. Реестр сетки

`configs/grid.json` заполняется **до** прогона: список семейств индикаторов и диапазонов параметров. Раннер:

1. считает SHA-256 файла сетки,
2. записывает хеш и время в `artifacts/run_meta.json`,
3. прогоняет **все** конфигурации и сохраняет все результаты, а не только лучшие.

Так мы сможем показать на защите: сколько конфигураций проверено, сколько прошло порог, сколько прошло бы случайно. Отбор победителя по максимуму без этой рамки — подгонка, и её на защите вскроют.

## 7. Метрики — определения зафиксированы

`P[t]` — цена (рублей за единицу иностранной валюты), меньше = лучше для клиента. Все горизонты `h` считаются **в наблюдениях ряда**, не в календарных днях.

**Попадание, «сейчас выгодно»** — курс остался не хуже в течение h:

```
hit_favorable(t, h) = min(P[t+1 .. t+h]) >= P[t]
```

**Попадание, «окно закрывается»** — курс действительно вырос за h:

```
hit_closing(t, h) = P[t+h] > P[t]
```

**Выгода момента.** Считать обе, обе выводить в отчёт:

```
benefit_sym(t, h) = mean(P[t-h .. t+h] \ {t}) / P[t] - 1     # определение ТЗ
benefit_fwd(t, h) = mean(P[t+1 .. t+h])      / P[t] - 1     # честная продуктовая проверка
```

Положительное значение = клиент выиграл, переведя в день сигнала. В базисных пунктах: `× 10000`. Значимость — t-тест с поправкой на автокорреляцию (Newey–West).

**Lift** — по hit rate, не по выгоде (подтверждено кейсодателем):

```
lift(h) = hit_rate(сигнальные дни, h) / hit_rate(все допустимые дни того же периода, h)
```

Из базы и из сигналов исключаются дни с перенесённым курсом (`is_carried`).

**Частота:** сигналов на коридор в неделю и в месяц.

**Кучность:** доля сигналов, у которых предыдущий сигнал был не далее 5 наблюдений назад, плюс коэффициент вариации интервалов между срабатываниями.

**Горизонты:** `h ∈ {1, 3, 5, 10, 20}` — все пять обязательны, главного кейсодатель не выделил.

## 8. Бэктест

* Walk-forward: расширяющееся обучающее окно, оценка на следующем out-of-time блоке (квартал).
* **Purging и embargo обязательны.** Метки с горизонтом `h` перекрываются во времени, поэтому наивный walk-forward всё равно протекает: обучающая метка заглядывает в тестовый период. Purging убирает перекрывающиеся наблюдения, embargo добавляет буфер в `h` наблюдений.
* Отчётность по периодам раздельно: до 2022 / 2022 / после 2022 / последние 12 месяцев.
* **Каждую конфигурацию прогонять и на фиксинге ЦБ, и на ценах закрытия MOEX.** Разница между прогонами — мера того, сколько в результате измерения, а не рынка. Это наш собственный найденный контроль: курс ЦБ есть средневзвешенная за день, а у доходностей «среднее к среднему» автокорреляция +0,25 по построению, безотносительно рынка.
