## Зачем

Код готов, данных нет.

Амир собрал индикатор `uzs_frozen_consensus` и экспортёр `fxpulse.frozen_uzs_replay`. Экспортёр читает результаты твоего финального прогона и делает из них два файла: replay для расчёта сигнала на произвольную дату и список дат для графика в прототипе. **Сам прогон в репозиторий не попал** — папка `artifacts/` в `.gitignore`, и у нас её нет.

Пока файла нет:

- **пункт 1 постановки** — «обязателен расчёт сигналов на произвольную дату среза» — закрыт только для базовых индикаторов, но не для модели, которую мы предлагаем в продукт. Это дисквалифицирующее условие кейса;
- **пункт 9** — «график курса по коридору с отметками срабатываний» — кривая построена, отметок нет. Восстановить ~30 дат из агрегированных метрик честно нельзя.

## Что нужно

Три файла из прогона финального UZS-эксперимента, в папке `artifacts/uzs_final_experiment_20260905/`:

| Файл | Что внутри |
|---|---|
| `policy_scores.csv.gz` | скор по каждой дате: `timestamp` и поля идентификации варианта |
| `signals.csv.gz` | сработавшие сигналы: `timestamp`, `signal_tier` |
| `run_meta.json` | метаданные прогона |

Идентификация замороженного варианта берётся из `configs/uzs_final_frozen_candidate.json`, трогать его не надо.

---

## Что сделать

```bash
uv run python -m fxpulse.frozen_uzs_replay
```

Команда по умолчанию читает `artifacts/uzs_final_experiment_20260905/` и пишет три файла:

- `models/uzs_frozen_oot_replay.csv.gz` — replay
- `models/uzs_frozen_oot_replay.manifest.json` — манифест с SHA-256
- `docs/prototype/signals-uzs.csv` — даты срабатываний за год для графика

Если папка прогона называется иначе, путь передаётся флагом `--artifact-dir`.

---

## Как проверить, что вышло правильно

Экспортёр сам сверяет метрики replay с опубликованными и падает, если расхождение больше 2,5 %. То есть если команда отработала без ошибки — числа сошлись с матрицей.

Дополнительно проверить глазами:

| Что | Ожидаем |
|---|---|
| Строк с `fired = true` | **140** |
| Период replay | 2022 — сентябрь 2026 |
| Дат в `signals-uzs.csv` | около 30 за последний год |
| `available_at` | дата плюс 20:00 МСК — время нашей отправки |

## Если прогон не восстанавливается

Тогда нужен любой из двух вариантов, в порядке предпочтения:

1. **Перезапустить финальный эксперимент** с тем же конфигом и seed — воспроизводимость мы и так заявляем, это её проверка.
2. **Отдать только список из 140 дат** с полями `date`, `signal_tier`, `strength`. Этого хватит для графика (пункт 9), но не хватит для расчёта на дату (пункт 1) — там нужен скор по всем дням, а не только по сработавшим.

Второй вариант закрывает половину задачи. Если выбираем его — скажи сразу, я перепишу формулировку в презентации, чтобы мы не заявляли то, чего нет.

## Почему replay, а не файл модели

Это стоит держать в голове на случай вопроса от жюри.

Победитель — **не одна модель**. Для каждого года проверки обучалась своя, на четырёх предыдущих годах. Если сохранить один файл, обученный по сентябрь 2026, и применить его к дате 2022 года — получится заглядывание вперёд, ровно то, что кейс дисквалифицирует.

Replay хранит решение той модели, которая реально работала в своём году, и проверяется по хешу. Для исторической демонстрации это корректнее одного общего файла.
