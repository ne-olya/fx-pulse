# Разметка данных для сигнальной модели

## 1. Что является объектом разметки

Одна строка — состояние рынка на момент `T` по одному инструменту и одной гранулярности.

Основная котировка: `P[T]` — рублей за единицу иностранной валюты. Чем `P` ниже, тем выгоднее момент для клиента.

Разметка рассчитывается автоматически по будущему окну. Будущие значения используются только для создания целевой переменной и оценки качества; в признаки модели они не попадают.

## 2. Какие поля хранить

Идентификаторы и контроль времени:

- `timestamp` — момент `T`;
- `series` — инструмент или коридор;
- `granularity` — `1d` или `1h`;
- `price_t` — цена, известная на момент `T`;
- `label_end_timestamp` — конец будущего окна;
- `is_valid` — достаточно ли будущих данных для расчёта;
- флаги переноса, пропуска и недостаточной ликвидности.

Для каждого горизонта `h`:

- `future_min_h` — минимальный курс в будущем окне;
- `future_mean_h` — средний курс в будущем окне;
- `future_end_h` — курс в конце окна;
- `waiting_benefit_bp_h` — выгода сегодняшнего момента относительно ожидания, в базисных пунктах;
- `good_now_h` — бинарная метка для сообщения «сейчас выгодно»;
- `window_closing_h` — бинарная метка для сообщения «окно закрывается».

Минимальное определение `good_now_h`:

```text
good_now_h = 1, если в следующие h периодов
не появился курс лучше сегодняшнего больше чем на epsilon_bp;
иначе 0.
```

Минимальное определение `window_closing_h`:

```text
window_closing_h = 1, если курс вырос к концу окна h
не меньше чем на delta_bp;
иначе 0.
```

`epsilon_bp` и `delta_bp` фиксируются в конфигурации до запуска эксперимента. Вместе с бинарными метками обязательно сохраняются непрерывные результаты в бп: это позволяет использовать одну разметку и для классификации, и для регрессии.

## 3. На каких данных размечать

Используем два уровня.

### Дневной уровень — обязательный MVP и контроль

- MOEX `CNYRUB_TOM`, дневной `close` — основной чистый контроль живого рынка;
- горизонты: `1/3/5/10/20` торговых дней — ровно по постановке задачи;
- курс ЦБ — только сопоставимый контроль, не основной сигнал, поскольку в нём обнаружен артефакт публикации.

С дневного уровня следует начать: на нём проще проверить направление курса, формулы меток, временные срезы и отсутствие утечки.

### Часовой уровень — основной эксперимент для внутридневного сигнала

- MOEX `CNYRUB_TOM`, свечи `1h`;
- короткие горизонты: `1/4/8/24` следующих торговых свечи;
- продуктовые горизонты `1/3/5` торговых дней проверяются отдельно на дневном датасете.

Часовой уровень нужен, если хотим выбирать момент отправки внутри дня. Он даёт больше наблюдений, но содержит больше шума и сильнее пересекающиеся будущие окна. Полноту часовой истории и ликвидность необходимо подтвердить в отчёте о качестве данных.

Для первого прототипа порядок такой: сначала дневная разметка и рабочий бэктест, затем та же схема на часовых данных. Более мелкие интервалы пока не нужны.

## 4. Признаки хранятся отдельно

В таблицу признаков входят только данные, доступные на `T`: прошлые доходности, перцентили, расстояние до минимума, волатильность, объём, число сделок, время суток и календарные признаки.

`future_*`, `waiting_benefit_*` и бинарные метки запрещено использовать как признаки.

## 5. Для каких подходов подходит разметка

- правила и индикаторы оцениваются по этим меткам;
- Logistic Regression, CatBoost и другие классификаторы предсказывают `good_now_h` или `window_closing_h`;
- GRU/LSTM получают последовательность прошлых значений, но предсказывают те же метки;
- регрессия предсказывает непрерывную выгоду в бп.

Нужна отдельная метка для каждого сценария и горизонта. Разделение train/validation/test выполняется по времени; между частями ставится purging/embargo не меньше максимального горизонта разметки.
